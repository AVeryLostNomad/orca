---
title: Monaco editor & autosave
---

Orca's code editor is Monaco — the same editor VS Code uses — with a few Orca-specific tweaks.

## Autosave

Files save on blur and after short idle periods. There is no "dirty" dot because there are no unsaved changes in normal flow.

## Multi-cursor, go-to, find

- `Cmd-D` — select next occurrence.
- `Cmd-F` / `Cmd-Shift-F` — file find / worktree find. File find seeds the search box from the current selection when text is selected.
- `Cmd-Click` — go to definition (where supported by language extensions).

## Changes view mode

Toggle **Changes view mode** in any editor tab to flip the file into an in-tab HEAD-vs-working-tree diff without leaving your cursor position. Same shortcuts as the [Diff viewer](/docs/review/diff-viewer) — `n`/`p` to walk hunks, `s` to stage. Toggle again to return to the regular file view.

Git baseline reads distinguish an empty file, a missing file, and an unavailable read. A failed diff read shows an error with **Retry**, never error text masquerading as file contents. Ordinary editor baseline refreshes do not replace unsaved text. Plain folder workspaces and external files do not acquire repository baselines.

Ordinary code editors show HEAD-relative Git gutters: green for additions, blue for replacements, and red divots for deleted lines. Markers follow unsaved edits and undo, and refresh when HEAD changes without replacing the working buffer. Missing, oversized, or unverifiable baselines produce no markers; plain folder workspaces do not show Git gutters.

## Editable working diffs

In Source Control, single-click a file to preview its diff, including Markdown; double-click to open its current working file in a permanent editor tab. Renames use the current destination path. Missing files stay in review, and conflicts keep their resolver. Split-open modifiers reuse the split from the first click. In a combined diff's file navigator, single-click scrolls to the section and double-click opens the working file.

The current working-copy side of an unstaged diff is editable, including text rows in **View all**. The ordinary editor, Changes mode, individual working diff, and combined diff share the same text and undo history. Collapsing a combined row or closing one view does not discard edits that another view still owns.

Save and autosave use one file queue across these views. Closing the final view prompts for unsaved changes; failed saves preserve them. Unsaved combined-only edits are recovered as ordinary file tabs after restart and require disk verification before autosave resumes. Staged, historical, pull-request, and deleted-file snapshots remain read-only.

## Whitespace comparison

With **Show Whitespace** off, diffs ignore only proven-safe spaces and tabs at code-line edges in JavaScript, TypeScript, JSON, and inside HTML tags. Text nodes, attribute values, comments, multiline literals, Python indentation, Markdown hard breaks, and uncertain syntax remain literal. Turning the option on compares whitespace literally. Both modes ignore CRLF versus LF encoding differences but preserve final-newline changes.

This policy affects comparison only: editing, copying, saving, and expanded snapshot context retain the original text. Comparison failures show a retry action without discarding the working document.

## Word wrap

File editors wrap long lines by default. Toggle **Word Wrap** from the editor tab's **⋯** menu, press `Alt+Z` (same as VS Code; remappable under [Settings → Shortcuts](/docs/settings)), or set the default under [Settings → General → Editor Word Wrap](/docs/settings). This setting is separate from **Diff Word Wrap**, which only affects diff editors.

## Minimap

A minimap is available in the file editor under [Settings → Appearance](/docs/settings). It's off by default; turn it on if you prefer the VS Code-style overview rail.

## Custom editor font

By default the editor and diff views use the same font as the terminal. Leave **Editor Font Family** empty under [Settings → Appearance](/docs/settings) to keep that link; set a font to override editors only (UI font stays separate).

## Language support

Syntax highlighting ships for the languages Monaco supports out of the box. Orca is intentionally editor-first, not IDE-first — run type-checkers and linters in a terminal pane.
